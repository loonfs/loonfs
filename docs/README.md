# Documentation map

The documentation tree is arranged so the team can answer four different questions quickly.

- `specs/`: What is the intended behavior?
- `adr/`: Which design choices are already decided? ("ADR" = Architecture Decision Record)
- `roadmap/`: What order should we implement things in?
- `runbooks/`: How do we debug or operate common workflows?
- `references/`: Which external ideas informed this repo?
- `context/`: What user/design input started the work?


Recommended first reading for implementers:

1. `specs/000-overview.md`
2. `specs/060-testing-strategy.md`
3. `specs/090-major-implementation-decisions.md`
4. `adr/` in numerical order
5. `roadmap/020-semantic-core-reset.md`
6. `roadmap/010-foundation-workstreams.md` for the original workstream breakdown
